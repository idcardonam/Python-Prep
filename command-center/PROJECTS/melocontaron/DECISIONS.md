# DECISIONS — Decisiones y por qué

## 2026-08-04 — Fase aclaración / no codear aún
**Decisión:** Quedarse en fase `aclaracion` hasta cerrar P0 (MVP, offline/LAN, quién pide, capacidad, parqueadero, factura).  
**Por qué:** Alcance grande + internet débil + FE legal; inventar stack o FE completa rompería plazos.  
**Alternativa descartada:** Empezar código full-stack sin MVP.  
**Impacto:** Primero análisis, wire del flujo y checklist; código tras aprobación de millas/MVP.  
**Quién validó:** pendiente Iván / dueño.

## 2026-08-04 — MVP propuesto (pendiente OK)
**Decisión (propuesta):** V1 = cuenta titular + vehículos + mesa + pedido + pago (efectivo/transferencia) + cola cocina con checks/notas/alertas + salida parqueadero + carta QR lectura + cierre diario básico. Inventario recetas, FE DIAN, web marketing y analítica avanzada = fases siguientes.  
**Por qué:** Ataca el dolor real (atrasos, pedidos incompletos, salida sin pago, cero trazabilidad).  
**Alternativa descartada:** “Todo el aplicativo contable + FE + promos + web” en un solo golpe.  
**Impacto:** Entrega útil más pronto; reduce riesgo de no adopción.  
**Quién validó:** pendiente.
